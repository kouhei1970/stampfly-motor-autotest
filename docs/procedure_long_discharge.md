# 長時間放電による等価抵抗 R_out の電池電圧依存の測定（手順書）

作成 2026-10-30。状態: 計画（未実施）。

## 1. 目的

StampFly の駆動回路（モータに並列のコンデンサ $C_C$ で還流する構成）は、1 周期で平均すると、電池電圧と逆起電力の間に等価抵抗 $R_\text{out}(D, C_C)$ が入った形で表せる。

$$\bar I_m = \frac{V_{DD} - K_e\,\omega}{R_\text{out}(D, C_C)}$$

この式は「$R_\text{out}$ は電池電圧によらない」ことを前提にしている。ところが 2026-10-15 のベンチは電池電圧 4.17〜4.38 V だけで、この前提を確かめた範囲は狭い。また飛行ログでは、ホバリングに要る Duty の電池電圧への依存が、この前提からの予測の半分ほどしか出なかった。

この試験では、満充電の電池でモータを約 4 分間回し続け、電池電圧が下がっていく間に $R_\text{out}$ を繰り返し測る。電源装置は使わない（電池と内部インピーダンスや応答が違い、結果が変わるおそれがあるため）。あわせて、ホバリング付近（Duty 0.6〜0.8）の $R_\text{out}(D)$ を 0.02 刻みで実測し、シミュレータ（SILS）の基準表を更新する。さらに、Duty を段差状に変えたときの回転数の動き（駆動中の過渡）を測る。2026-10-15 のデータにある過渡は駆動を切った後のスピンダウンだけで、駆動中の過渡はない。

## 2. 測る量と求め方

| 量 | 測り方 | 備考 |
|---|---|---|
| $V_{DD}$（基板の電池側の電圧） | オシロ CH2、基板近くのケーブル分岐。1 回の取り込みの平均 | 解析の入力。電池の内部抵抗による低下はこれに含まれる |
| ドレイン電圧 $v_D$ | オシロ CH1 | 実測 Duty と回転数の計算に使う |
| 角速度 $\omega$ | PWM 1 周期ごとの $V_{DD}-v_D$ の平均を FFT し、脈動の周波数 $f$ から $\omega = 2\pi f / N$（$N = 10$） | 2026-10-15 と同じ方法 |
| 電池電流 $I_\text{bat}$ | CLI の `sensor power`（シャント修正後のファーム） | 構成 A では平均の電池電流 = 平均のモータ電流 |
| モータ缶の温度 | 熱電対をモータ缶に貼り、記録計で連続記録（なければ非接触温度計で停止時のみ） | 巻線抵抗は 1 K あたり約 0.4 % 変わる |
| 推力 | 秤の写真（参考） | $R_\text{out}$ の計算には使わない。ゼロ点は運転の前後で記録 |

各測定点で次を計算する（$K_e = 5.905\times10^{-4}$ V·s/rad）。

$$R_\text{out,meas} = \frac{V_{DD} - K_e\,\omega}{I_\text{bat}}$$

Duty は指令値（ファームと SILS が受け取る値）で整理し、実測 Duty も併記する。

## 3. 判定（測る前に決めておく）

| 比べるもの | 前提「$R_\text{out}$ は電池電圧によらない」が正しければ | 正しくなければ |
|---|---|---|
| 同じ Duty の「冷えた状態・高い電圧」（開始直後）と「冷えた状態・低い電圧」（冷却後の再測定） | 差は繰り返しのばらつき程度（目安 ±2 %） | 電圧の差に応じて系統的に違う。1 V あたり何 % かを出す |
| 同じ Duty の「熱い状態・低い電圧」（4 分の終わり）と「冷えた状態・低い電圧」 | 差は温度の効果だけで、巻線抵抗の温度係数から見積もれる大きさ | — |
| 4 分間の連続データの $R_\text{out}$ 対 $V_{DD}$ | 缶温度で補正すると傾きがほぼ 0 | 補正後も傾きが残る |
| Duty ステップでの $\omega(t)$ と、非線形の式を数値で解いた軌道（9 章） | 正規化した軌道 $(\omega-\omega_0)/(\omega_1-\omega_0)$ の差が、段差の間ずっと 0.1 以内 | 差が 0.1 を超える。速い・遅いのどちら向きか、どの段差（上げ・下げ・大小）で起きるかを出す |

## 5. 安全

- プロペラ付きで約 4 分回す。保護具を使い、機体を固定し、回転面に手や線を近づけない。
- 熱電対の線は回転面から離して固定する。
- 次のどれかになったら、すぐ `motor stop` で止める。
  - 負荷中の $V_{DD}$ が 3.5 V を下回った
  - 缶の温度が、あらかじめ決めた上限（例: 70 °C）を超えた
  - 異音、焦げたにおい、機体の動き

## 6. 手順

### 準備

1. 室温、電池の番号、電池の無負荷電圧を記録する。
2. モータが冷えていること（缶の温度 ≒ 室温）を確かめる。
3. 配線をつないだ状態で秤のゼロを合わせ、ゼロの読みを記録する。
4. シリアル中継を起動する（別のターミナルで常駐）。

```bash
python3 tools/sf_serial_bridge.py
```

5. 別のターミナルで環境変数を設定する。

```bash
export SCOPE_IP=<オシロの IP>
export AUTOTEST_DATA=./data/long_discharge_<日付>_bat<番号>
export SF_CURRENT_SCALE=1
```

### 測定 A: 開始直後（冷えた状態・高い電圧）

6. Duty 周回を 1 周だけ測る（7 の周回と同じ Duty 列）。

### 測定 B: 約 4 分間の連続運転

7. 次の Duty 列を、止めずに繰り返す。各段 5 秒、各段で 1.5 秒待ってからオシロを取り込み（数秒かかる）、`sensor power` を読む。

| 順 | Duty [%] |
|---|---|
| 1〜12 | 50, 60, 62, 64, 66, 68, 70, 72, 74, 76, 78, 80 |

   1 周 60 秒で、4 分間で 4 周になる。指令は `motor test 1 <Duty%> 7`（7 秒）を各段の頭に送る。新しい指令が前の指令をその場で置き換えるので、段の切り替えでモータは止まらない（1 回の指令の上限は 60 秒）。
8. 240 秒たつか、5 章の停止条件に当たったら `motor stop` で止める。止めた時刻の缶の温度を記録する。

### 測定 C: 冷却後（冷えた状態・低い電圧）

9. 電池はつないだまま、モータだけを止めて冷ます。缶の温度が室温 +2 °C 以内に戻るまで待つ（目安 3〜5 分）。待ち時間を記録する。
10. 6 と同じ Duty 周回を 1 周だけ測る。電池は休ませた分だけ電圧が少し戻るが、$V_{DD}$ は各点で測るので問題ない。
11. 秤のゼロの読みを記録する。

### 繰り返し

12. 2 本目の電池で 1〜11 を繰り返す。このとき Duty 列を逆順（80 → 50）にして、順番の影響を見る。Duty の指定は整数の % だけ（ファームの `motor test` の仕様）。

### 測定 D: Duty ステップ（駆動中の過渡）

回転の式は $\omega$ について非線形なので、過渡は時定数では整理しない。実測の $\omega(t)$ と、同じ指令 Duty と実測の $V_{DD}(t)$ を入れて非線形の式を数値で解いた軌道を比べる（9 章）。

長時間放電の基準点（冷えた状態・高い電圧）を乱さないよう、次の 2 回に分けて行う。

| 回 | いつ | 電池 |
|---|---|---|
| D-低 | 測定 C の直後（モータは冷えた状態から始まる） | 長時間放電に使った電池（電圧が低い） |
| D-高 | 別の日、または長時間放電の前に、モータが冷えた状態で | 別の満充電の電池 |

13. オシロを長時間の取り込みに設定する。

| 設定 | 値 |
|---|---|
| 時間軸 | 100 ms/div（画面 12 div で約 1.2 秒） |
| メモリ長 | 2 チャネルで最大（12 Mpts。約 10 MS/s、PWM 1 周期あたり約 66 点） |
| トリガ | 単発。PC から強制トリガ（`:TFORce`）をかけ、記録の先頭から約 0.1 秒後に段差が来るようにする |
| チャネル | CH1 ドレイン、CH2 $V_{DD}$（ほかの測定と同じ） |

14. 次の段差を順に行う。各段差の前に、段差前の Duty で 2.5 秒以上回して定常にしてから、強制トリガ → 約 0.1 秒後に段差後の Duty の `motor test` を送る。取り込みの読み出し中も、モータは段差後の Duty のまま回してよい（読み出しが終わったら次の段差の段差前の Duty へ移る）。

| 番号 | 段差前 → 段差後 [%] | 見るもの |
|---|---|---|
| S1 | 0 → 60 | 回し始め（止まった状態から） |
| S2 | 60 → 68 | ホバリング付近の小さな上げ |
| S3 | 68 → 60 | 同じ幅の下げ |
| S4 | 50 → 80 | 大きな上げ |
| S5 | 80 → 50 | 大きな下げ |
| S6 | 60 → 0 | 駆動を切った後の減速（10-15 のスピンダウンとの照合） |

15. 段差の時刻は、PC の送信時刻ではなく、ドレイン波形で PWM の幅が変わった周期から決める（シリアルの遅れを含まないようにするため）。
16. 各段差の取り込みの前後に `sensor power` を読み、缶の温度を記録する。

## 7. 記録する項目

| 区分 | 項目 |
|---|---|
| 全体 | 日付、室温、電池番号、電池の無負荷電圧（開始前・終了後）、ファームのコミット、秤のゼロ（開始前・終了後） |
| 各測定点 | 経過時間、区分（A・B・C）、指令 Duty、実測 Duty、$V_{DD}$、$\omega$、$I_\text{bat}$、CLI の電圧、缶の温度、秤の写真 |
| 停止 | 停止の理由、時刻 |
| Duty ステップ | 回（D-低・D-高）、段差の番号、段差前後の Duty、段差の時刻（波形から）、取り込みの前後の $V_{DD}$・電流・缶の温度、波形ファイル名 |

## 8. 必要なスクリプト（`tools/exp_long.py`、未作成）

既存の `tools/exp_auto.py` は 1 段ごとに止めて前後の読みを取る作りなので、連続運転用を別に作る。必要な動きは次のとおり。

| 機能 | 内容 |
|---|---|
| Duty 周回 | Duty 列・各段の時間・総時間・周回数を引数で受け、各段の頭に `motor test 1 <Duty%> <段の時間 + 2>` を送る |
| 取り込み | 各段で待ち時間の後にオシロの 2 チャネルを取り込み、$\omega$・実測 Duty・$V_{DD}$ の平均を計算する（`exp_rpm.py` の計算を流用） |
| 電流 | 各段で `sensor power` を 1〜2 回読む |
| 温度 | 記録計の出力を時刻で突き合わせる（記録計が PC につながらない場合は、手で読んだ値を後から入れる） |
| 停止 | $V_{DD}$ の下限と総時間で自動停止し、Ctrl-C でも必ず `motor stop` を送る |
| 出力 | 1 点 1 行の CSV（7 章の項目）と、取り込んだ波形の要約 |
| Duty ステップ | 段差の列を引数で受け、段差前の Duty で待つ → オシロを単発・長時間の設定にして強制トリガ → 段差後の Duty を送る → 波形を全点読み出す、を繰り返す |
| 過渡の計算 | PWM 1 周期ごとに $V_{DD}-v_D$ の平均・$V_{DD}$ の平均・実測 Duty を求め、その系列の脈動の周波数をずらしながら（例: 窓 10 ms、刻み 2 ms）求めて $\omega(t)$ にする。段差の時刻は実測 Duty の変化点から決める |

## 9. 解析と結果の使い道

1. 各点の $R_\text{out,meas}$ を計算し、Duty ごとに $V_{DD}$ と缶温度に対して並べる。
2. 3 章の比較を行い、「電圧の効果」と「温度の効果」を 1 V あたり・1 K あたりの % で出す。
3. 電圧の効果がない場合: 0.02 刻みの $R_\text{out}(D)$ を SILS の基準表に入れる（今の表は 0.1 刻みの 9 点を元にしている）。
4. 電圧の効果がある場合: $R_\text{out}(D, V_{DD})$ として表を 2 次元にし、ファームの推力 → Duty 変換に使う前に影響を見積もる。論文の改訂では、電圧によらないことを確かめた範囲を明記する。
5. Duty ステップ: 段差の時刻から、指令 Duty の段差と実測の $V_{DD}(t)$ を入れて、次の式を段差前の定常の $\omega$ から数値で解く（$R_\text{out}$ は同じ回の実測を使う）。

$$J\,\dot\omega = K_t\,\frac{V_{DD}(t) - K_e\,\omega}{R_\text{out}(D(t))} - C_Q\,\omega^2 - K_t\,I_0(\omega)$$

   実測と計算の軌道を、段差前後の定常値で正規化して重ね、3 章の基準で判定する。S6（駆動を切った後）は、10-15 のスピンダウンと同じ形になるかも確かめる。合わない場合は、どの項（慣性 $J$、電気的な制動 $K_tK_e/R_\text{out}$、空力・摩擦）を変えれば合うかを、段差の向きと大きさごとの食い違い方から調べる。時定数の当てはめは行わない（線形化した時定数が意味を持つのは、動作点のまわりの小さな変化だけ）。
6. 結果は stampfly_ecosystem の `analysis/notes/ct_cq_bench_20261015.md`（8 章「残る課題」）に反映する。
